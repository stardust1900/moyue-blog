我的博客在github pages和edgeone pages上都部署了，问了一下元宝哪个访问速度更快。

一下是它的回答。

## 结论：https://blog.wangxuan.me 在中国（含南京）明显更快

而且差距不是"快一点"，是两个量级的差别。

## 我查到的证据（DNS 实测）

| | wangxuan.me | blog.wangxuan.me |
|---|---|---|
| 解析结果 | A 记录直指 `185.199.108~111.153` | CNAME 到 `blog.wangxuan.me.pages.dnsoe7.com` → `43.174.246/247.101` |
| 托管方 | **GitHub Pages**（仓库 stardust1900.github.io），CDN 是 Fastly | **腾讯云 EdgeOne Pages**（`dnsoe` 是 EdgeOne Pages 的 CNAME 接入域名），IP 属腾讯云 ASN |
| 大陆节点 | 无。北京访问常被路由到东京/香港 PoP，跨境跳转 | 亚太边缘节点，国内解析命中腾讯边缘网络 |
| www 子域 | `www` → stardust1900.github.io（IPv6 2606:50c0:800x::153） | — |
| 图片域 | `photo.wangxuan.me` → 也是 EO（`43.174.x`） | — |

关键点：**GitHub Pages 的 4 个 IP 正是官方固定地址，全球靠 Fastly Anycast 广播，中国大陆境内没有节点**；而 `dnsoe` 系域名与腾讯云 EdgeOne Pages 的分配格式一致，国内解析会直接落到腾讯的边缘节点。

## 国内访问速度的大致区间

- **GitHub Pages（wangxuan.me）**：延迟看着可能不算夸张，但带宽极低、丢包抖动大，图片加载尤其卡，晚高峰和部分地区会出现明显变慢甚至打不开
- **EdgeOne Pages（blog.wangxuan.me）**：国内延迟通常稳定在 100–250ms 量级，波动远小于 GitHub Pages；若域名完成 ICP 备案并启用大陆节点，可进一步压到 100ms 以内

**顺带提醒**：你的图片域名 `photo.wangxuan.me` 已经在 EO 上了，但主站根域 `wangxuan.me` 还挂在 GitHub Pages 上——等于"图片快、HTML 慢"，首屏打开还是被根域拖住。

## 你本地 30 秒验证（南京，最能说明问题）

我这边的沙盒网络被出口策略拦住，无法对这两个域名做端到端计时，所以上面的判断基于 DNS/IP 归属和托管架构，加上公开的多地实测数据。你在本地跑一下就能拿到真实数字：

```bash
for u in https://wangxuan.me https://blog.wangxuan.me; do
  echo "== $u =="
  for i in 1 2 3; do
    curl -o /dev/null -sS -A "Mozilla/5.0" -w "DNS:%{time_namelookup}s TCP:%{time_connect}s TLS:%{time_appconnect}s TTFB:%{time_starttransfer}s 总计:%{time_total}s 速率:%{speed_download}B/s\n" "$u"
  done
done
```

重点看 **TTFB** 和 **速率** 两项，跑三次取中位数。想看多运营商/多省份对比，可以上 ITDog 的 HTTP 测速页（itdog.cn/http/）贴链接跑一遍。

## 想让 wangxuan.me 也快起来

1. **最省事**：把根域也部署到 EdgeOne Pages，根域用 DNS 的 CNAME Flattening / ALIAS 指到 EO 分配的 CNAME，全站统一到国内边缘节点（跟 blog 和 photo 一致）。
2. **保持 GitHub Pages 不变**：在根域前面套一层国内 CDN（腾讯云 EdgeOne 或阿里云 ESA）回源到 GitHub Pages，社区实测能提速 60%–85%。
3. **注意合规**：域名若已备案，EO/ESA 可启用大陆节点，速度还能再上一个台阶；未备案则走国际站，仍是亚太节点。

把本地跑出来的数字贴给我，我帮你判断要不要动手迁移。
